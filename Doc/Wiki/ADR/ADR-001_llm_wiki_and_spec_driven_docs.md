# ADR-001: LLM Wiki＋Spec駆動ドキュメント管理アーキテクチャの採用

## ステータス
**承認済 (Accepted)** - 2026-09-18

## コンテキスト
CreateStudioは、複数のAIエージェント（Director, Generator, Critic, Assembler等）が協調して動作する複雑なシステムです。  
従来の手動ドキュメント管理では、コード修正に伴う仕様書の陳腐化、設計判断理由の散逸、エラー発生時の教訓が引き継がれないといった問題（ドキュメントの腐敗）が発生します。  
先行プロジェクト「TarotDiary」では、Andrej Karpathy氏が提唱する「LLM Wiki」思想と「Living Documentation（Spec駆動）」を融合した運用により、極めて高い保守性と自己修復性を実現していました。

## 決定事項
本プロジェクトにおいても「TarotDiary」の設計に倣い、以下のドキュメント構造を標準採用する。
1. **`Doc/Spec/` (確定仕様)**: 現在の動作・データスキーマ・インターフェースを記述するLiving Docs。コード変更時は必ず同期更新。
2. **`Doc/Wiki/` (ナレッジ)**: 「なぜその設計にしたのか (ADR)」「過去の失敗と恒久策 (Troubleshooting)」を永続蓄積。
3. **`Doc/Plan/` (計画・進捗)**: マイルストーン、各フェーズの進捗状況をリアルタイム管理。
4. **双方向リンクの強制**: 仕様書とADR/知見を相互リンクし、トレーサビリティを100%確保する。

## トレードオフ & 影響
- **メリット**: コードの意図が常に明確化され、新機能開発やデバッグ時にAIが迷わず一貫した実装を行える。
- **留意点**: ドキュメント作成・更新のオーバーヘッドが発生するため、エージェントスキル（`llm_wiki`）によって更新を半自動化・ルール化する。
